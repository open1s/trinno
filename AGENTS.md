# AGENTS.md

## Project

**trinno-research** ("Trinno Research Assist") — VS Code extension. Adds a Trinno Chat research-assistant sidebar (TRIZ tools, paper downloader, slash commands, slash-tool execution) on top of the Jupyter notebook host. Project name in `package.json` is `trinno-research`; old internal name `vscode-jupyter-typst` is no longer accurate.

## Don't edit

- `node_modules/`
- `dist/` (build output; regenerated by `npm run compile`)

## Commands

```
npm run compile       # tsc -p ./ && rm -rf dist/chat/webview && cp -r src/chat/webview dist/chat/webview
npm run watch         # tsc -watch -p ./
npm run test          # node ./dist/test/runTest.js  — launches real VS Code via @vscode/test-electron
npm run test:pipeline # npx mocha dist/test/suite/research-project-pipeline.test.js — single-file mocha run
npm run lint          # eslint src/chat/*.ts   (config: eslint.config.js; ignores src/bos/)
```

- `npm run compile` **must succeed before `npm run test`** — tests load from `dist/`.
- The compile script copies `src/chat/webview/` over `dist/chat/webview/`. If you change webview files, recompile.

## Package manager

Three lockfiles exist: `bun.lock`, `package-lock.json`, `yarn.lock`. `package.json` declares `packageManager: yarn@4.13.0`. Convention in this repo: **use npm** (tests + compile were verified with `npm`; lockfile coexistence is not yet cleaned up).

## Workspace model (TRP)

Trinno expects a "Trinno Research Project" folder containing 7 phase directories. The phase layout is what every slash command's `PhaseWriter` targets:

```
<workspace>/
  01_Discover/     free-form exploration
  02_TRL/          S-curve / TRL assessments
  03_Analyze/      contradictions, ideality, su-field
  04_Synthesize/   inventive principles, solutions
  05_Deliver/      selected concepts
  06_References/   downloaded papers, search results
  07_Patent/       patent drafts
```

- Workspace root is set via `trinno.chat.trpWorkspace` setting, or auto-detected as the first sub-folder with 3+ of these phase dirs, or the first VS Code workspace folder.
- **/init slash command** (`src/bos/slash-commands/init.ts`) creates missing phase dirs + a starter `README.md`. Safe to re-run; never overwrites.
- Default paper download destination is `<workspace>/06_References/`.

## Architecture

```
src/
  extension.ts          # entrypoint — activate/deactivate
  output/               # output-channel utilities
  chat/                 # Research assistant panel
    panel.ts            # webview host, slash dispatch, session storage
    agent.ts            # agent process spawner
    compaction.ts       # conversation-history summarization
    webview/            # pre-built JS webview (chat.js + lib/* + styles.css)
                         # NOT compiled by tsc; copied verbatim to dist/chat/webview/
  papers/               # Paper downloader
    downloader.ts       # races 9+ sources, format detection, write-to-disk
    sources/            # arxiv, biorxiv, openalex, zenodo, crossref, publisher_direct, ...
    identifier.ts       # DOI/arXiv/PMID/URL parser
    racer.ts            # source-race coordinator
  bos/                  # BOS framework — tsc-excluded (see below)
    worker.ts           # process entry; receives JSON-over-stdio from panel
    slash-commands/     # one file per /command (registry.ts, init.ts, contradiction.ts, ...)
    domain/             # pure logic: contradiction, principle, solution, s_curve
    application/        # use-cases: analyze_contradiction, evaluate_ideality, ...
    infrastructure/     # ai, config/di.ts, http/ (triz_tools, papers_tools, coding_tools),
                         # persistence/ (phase_writer, raw_facts_saver), search/
  test/suite/           # Mocha + @vscode/test-electron
```

### Tool & slash-command registration

- **Slash commands** are registered in `src/bos/worker.ts` (~line 47) via `slashRegistry.register(cmd, aliases?)`. To add a new command: create `src/bos/slash-commands/<name>.ts`, export from `index.ts`, register in `worker.ts`, **and** add an entry to `staticSlashCommands` in `src/chat/panel.ts` (line ~189) AND to the hardcoded fallback list in `src/chat/webview/chat.js` (line ~60). The webview's hardcoded list is used for completion-popup before the welcome message arrives.
- **AI tools** are defined in `src/bos/infrastructure/http/triz_tools.ts` and `src/bos/infrastructure/http/papers_tools.ts` using `@open1s/ezbos`'s `defineTool().required().param().handle()`. They're wired into the agent in `src/bos/infrastructure/config/di.ts` (`composeRoot` returns them in `deps.tools`).
- **Workspace root propagation**: the panel reads `trinno.chat.trpWorkspace` (or auto-detects) and must pass it as the **last argument** to `sendMessage` (signature has it) and `sendSlashRequest` (no signature — pass `getDefaultWorkspaceRoot()` as the 7th arg). The worker stashes it in `globalThis.__TRP_WORKSPACE_ROOT`, then `composeRoot` reads it. The worker defaults to `process.cwd()` if the panel didn't pass one — that's the wrong place (VS Code install dir), so always pass `getDefaultWorkspaceRoot()` from the panel.

### `src/bos/` is tsc-excluded but editable

`tsconfig.json` excludes `src/bos`. Consequence:
- `tsc` will not typecheck it. `npm run compile` succeeds even with errors there.
- The worker process is run at dev time via `tsx` (devDep), which uses on-the-fly transpilation.
- Your editor's LSP may not resolve `@types/node`, `@open1s/ezbos`, `vscode`, `fetch`, `Buffer`, `process`, etc. inside `src/bos/` — these are **noise**; trust `npm run compile` and the runtime, not the LSP red squiggles.
- `eslint.config.js` also ignores `src/bos/`.
- If a new file in `src/bos/` is type-sensitive (e.g., a new tool), run `npm run compile` to confirm.

### Paper downloader wiring

- Default output: `<workspace>/06_References/`. Falls back to `~/.trinno/papers/` if not writable.
- Sources raced (in rank order): arxiv → biorxiv → openalex → zenodo → publisher-direct (Frontiers/MDPI/PLOS/PeerJ by DOI prefix) → crossref → semantic-scholar → europe-pmc → unpaywall.
- Format auto-detected from Content-Type, buffer magic (`%PDF-`, `PK\x03\x04`, `{\rtf1`, `<html`/`<!DOC`), or URL extension. Accepted: PDF, DOCX, DOC, EPUB, HTML, RTF, TXT, ZIP, etc.
- The downloader module lazy-`require('vscode')` (see `readConfiguredOutputDir`); safe to import from non-VS-Code contexts (the worker) as long as you pass an explicit `outputDir`.

## Testing

- Framework: Mocha + `@vscode/test-electron` (launches real VS Code instance with `--disable-extensions`).
- Test files: `src/test/suite/`. Each file is its own test entry.
- Single-file run: `npm run test:pipeline` (or adapt the path).
- E2E tests (`session-e2e.test.ts`, `chat-e2e.test.ts`, `workspace-root-e2e.test.ts`) require the worker process to be spawnable — they may be slow or flaky in headless environments.

## TypeScript

- All strict flags on, including `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `useUnknownInCatchVariables`. Watch for these:
  - `exactOptionalPropertyTypes`: `{ error?: string }` cannot accept `error: undefined`; either omit the key or normalize to `string`.
  - `noUncheckedIndexedAccess`: array/record access is `T | undefined`; you must narrow before use.
- Target: ES2020, CommonJS, `moduleResolution: node`. Imports use `.js` extension even for `.ts` files (per `module: commonjs` resolution).
- `@types/vscode` pinned to `^1.120.0` (recent API). `@types/node` is in devDeps and applies to `src/` (but not to `src/bos/` for LSP).
- `ignoreDeprecations: "6.0"` set (TypeScript 6 deprecation noise is silenced).
