# Trinno Agent Configuration

## Operational Profile

### When to Prioritize Scope Over Speed
- Security: Never skip `.instructions.md` checks
- Compilation: Always verify `npm run compile` succeeds
- Testing: Run relevant tests before marking done
- Architecture: Respect CONTEXT.md domain model

### When to Prioritize Speed Over Scope
- Typos in comments: Fix inline, don't open new issue
- Minor lint warnings: Fix if touching that file anyway
- Docstring formatting: Normalize only your changes
- Demo project: Never modify demo/ unless explicitly asked

## Working Heuristics

### File Reading
- If error mentions a line number → read that line ±5 context
- If asking "how does X work" → search for X's definition + usages
- If seeing unfamiliar API → check CONTEXT.md domain model first
- Never read >500 lines unless necessary; use grep_search to narrow

### Task Claiming
- Always say what you're doing BEFORE using tools
- If multiple interpretations exist, ask one clarifying question
- If uncertain about scope, ask: "Should I also [related task]?"
- Always update todo list after completing atomic tasks

### Response Discipline
- Max 4KB per response; if exceeding, say "Next: [name]"
- No "As an AI I would..." preface
- No speculative features ("you could also...")
- Confirmation statements only after successful verification

### Error Recovery
- LSP red squiggles in `src/bos/` → Always ignore; trust `npm run compile`
- Test import errors → Run `npm run compile` immediately
- Worker process timeouts → Check for infinite loops in new logic
- Attachment formatting broken → Verify hybrid_attachment_strategy.md compliance

## Phase Workflow Reminders

### When Adding Slash Commands
Checklist:
- [ ] Command file: `src/bos/slash-commands/<name>.ts`
- [ ] Export in: `src/bos/slash-commands/index.ts`
- [ ] Register in: `src/bos/worker.ts` (~line 47)
- [ ] Add to: `src/chat/panel.ts` staticSlashCommands (~line 189)
- [ ] Add to: `src/chat/webview/chat.js` hardcoded list (~line 60)
- [ ] Test: `npm run compile` succeeds

### When Modifying Papers Downloader
Remember:
- Default output: `<workspace>/06_References/`
- Fallback: `~/.trinno/papers/`
- Sources ranked: arxiv → biorxiv → openalex → zenodo → publisher-direct → crossref → semantic-scholar → europe-pmc → unpaywall
- Format detection: Content-Type, magic bytes, extension

### When Changing Workspace Root Logic
Propagation chain:
- Panel reads `trinno.chat.trpWorkspace` (or auto-detects)
- Panel passes to `sendMessage(..., workspaceRoot)` + `sendSlashRequest(..., workspaceRoot)`
- Worker stashes in `globalThis.__TRP_WORKSPACE_ROOT`
- `composeRoot()` reads it for DI container

## Known Friction Points

### TypeScript Strictness
- `exactOptionalPropertyTypes`: `{ x?: string }` can't accept `undefined` value
- `noUncheckedIndexedAccess`: array[i] is always `T | undefined`
- Fix: Null-check before use; use `??` for optional chains

### src/bos/ LSP Noise
- Unresolved imports in `src/bos/` are normal (intentionally not typecheck'd)
- `@types/node`, `@open1s/ezbos`, `vscode` are all available at runtime
- Solution: Ignore LSP; trust `npm run compile` + test run

### Webview Not Updating
- Changes in `src/chat/webview/` require `npm run compile` to copy to `dist/`
- Symptom: UI change doesn't appear in running extension
- Fix: Always run `npm run compile` after webview edits

### Worker Process Crash
- Worker runs in parallel process; crashes don't surface in extension logs
- Check: Run `npm run test` to see actual error
- Debug: Add console.log in `src/bos/worker.ts` and check VS Code output panel
