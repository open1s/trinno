# 17 混合附件策略（ADR-001）：让大上下文既经济又准确

要让 AI 读懂你的代码与文档，必须先把上下文"喂"给它。但当文件很大时，**全量内联**既烧 token 又易过时，**纯引用**又增加往返。TRINNO 在 ADR-001 中给出的解法是**混合附件策略**：按规模在"内联"与"引用"之间自适应切换。

## 一、三种附件来源

用户可通过三种方式注入上下文：

- **Send Selection**：发送选区代码；
- **Send Current File**：发送当前文件；
- **Choose File**：选择文件发送。

每条附件要么是**内联**（全文直接嵌入消息），要么是**文件引用**（仅给路径 + 行范围 + 预览，由 LLM 按需 `read_file` 读取）。

## 二、混合判定规则

```
内容 ≤ maxCharsPerAttachment（默认 2000）  →  内联全文（markdown 代码块）
内容 > 阈值                              →  文件引用 + 预览（~200 字 / 3–5 行）
                                          + 显式工具提示：
                                          Use read_file("path", startLine, endLine)
整本笔记本（notebook）                    →  始终以引用发送（含单元格头预览），不分大小
```

## 三、为什么是"混合"而非两极

- **纯内联**：对 AI 不需要的全文浪费 token，且内容在发送瞬间"快照"，易与当前文件**失同步**；
- **纯引用**：对一句就能答的小片段也多一次往返，拖慢首响应；
- **混合**：约 2000 字符的阈值恰好覆盖常见情形（如 ~30 行函数）内联划算，大文件与数据集走轻量引用。

引用模式让 LLM 读取**当前**文件状态而非陈旧快照，消息更轻、成本更低、上下文压力更小。整个 BOS worker 已有 `read_file` 工具（沙箱于工作区根），引用天然可信。

## 四、关联约束：输出截断与分块读取

为保证稳定性，工具输出上限为 **2000 行 / 50KB**，超出时全文存临时文件，模型仅见有界预览 + 提示用 Grep 或派生子智能体；`read` 工具默认 2000 行分页、显式告知续读位置。这些规则与混合策略共同构成"大上下文供给"的工程底座。

## 五、小结

ADR-001 的混合策略，本质是在 token 成本、内容时效性与往返开销之间求最优。下一期看执行侧的安全与回退——`/sandbox` 与 `/undo`。
