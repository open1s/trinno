# 18 /sandbox 与 /undo：让智能体"放开跑"也"随时退"

智能体的强大在于能执行命令、改写文件；风险也正在此处。TRINNO 用两层机制平衡"开放执行"与"安全可控"：**/sandbox** 把 shell 命令关进沙箱，**/undo** 提供基于版本控制的快照回退，使试错真正零成本。

## 一、/sandbox：命令的隔离边界

`/sandbox` 展示当前沙箱配置与状态（是否启用、可用工具、是否激活）。其底层按平台选择隔离手段：

- **macOS**：Xcode Command Line Tools 提供的 `sandbox-exec`；
- **Linux**：`bubblewrap`（`apt install bubblewrap`）；
- **Windows**：Sysinternals `psexec`（降级权限，非完全路径隔离）。

无论沙箱是否就绪，TRINNO 的**工具包装（tool wrapper）始终生效**——对文件路径做校验，将文件访问限制在**工作区根**之内。这是第一道、也是最稳的边界：即便沙箱缺失，越界访问仍被拦截。

## 二、为什么需要沙箱

智能体可能运行来自检索结果或自主研究的脚本。沙箱确保这些命令：

- 不能任意读写工作区之外的系统文件；
- 在受限环境中执行，降低误删/外泄风险；
- 与工具包装的路径边界叠加，形成纵深防御。

## 三、/undo：基于 jj 的快照回退

`/undo` 利用 **jj（Jujutsu）** 版本控制，回退智能体最近一次动作：

- **链式**：可多次 `/undo` 逐步回退到更早状态；
- **最佳场景**：智能体写文件或做改动后，发现方向错误可一键复原；
- **依赖**：使用 `/undo` 需先安装 jj（`brew install jj`）。

配合前面各期的产物落盘（TRP 阶段目录），回退是"项目级"的，而非仅对话级。

## 四、在智能体治理中的位置

`/sandbox` 与 `/undo` 与 `/goal` 的预算护栏（第 16 期）、`/auto` 的 `eval.md` 锁定（第 15 期）同属**治理层**：一个管"执行安全"，一个管"可恢复性"，一个管"方向不偏"，共同让自主行为可放心使用。

## 五、小结

沙箱 + 快照，使 TRINNO 既能"大胆探索"又能"一键回头"。下一期进入实证与交付的收口——文献实证与 `/patent` 专利草稿。
