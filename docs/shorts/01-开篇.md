# 01 TRINNO：融合 TRIZ·PRISMA·SWOT·PEST·5W1H·PICO 的有机 AI 智能体

TRINNO（Trinno Research Assist）并非基于单一方法论的工具，而是一系列经典方法论与 AI 智能体能力的**有机融合体**。其工具箱由六套框架构成——**TRIZ、PRISMA、SWOT、PEST、5W1H、PICO**——并以智能体为调度核心，依据问题性质**自适应地选择、排序与组合**框架，覆盖"问题界定—证据综合—创新求解—战略评估—环境校验"的完整认知闭环。

本文作为总纲，概览六套方法论在 TRINNO 中的角色与特征，重点说明其"方法论路由"所体现的智能，并阐明有机集成逻辑，为后续分册奠基。

## 一、方法论谱系：六套框架的角色与特征

### 1. TRIZ —— 发明问题解决理论（创新求解引擎）

TRIZ 通过对海量专利的归纳，主张"创新具有可复用的结构"。TRINNO 内置其完整工具链：

- **39 参数矛盾矩阵**：将改善/恶化诉求映射至 39 个通用工程参数空间，输出历史专利统计意义上的发明原理方向；
- **40 个发明原理**：跨域可迁移的创新"招式库"，支持关键词打分检索与实例索引；
- **物场（Su-Field）分析与 76 个标准解**：以"物质—场"建模刻画系统作用关系，识别有害/不足/过度三类非理想模式并给出标准解；
- **理想度（Ideality）**：以 `B / (C + H)`（收益 / 成本+危害）量化系统逼近"理想终态"的程度；
- **S 曲线 / TRL**：结合技术成熟度 S 曲线与 TRL（技术就绪等级 1–9），并可叠加 Gartner 技术炒作周期（Hype Cycle）评估生命周期位置。

- **特征**：结构化、可迁移、数据驱动；将"凭经验试错"升维为"沿历史解法方向收敛"。
- **在 TRINNO 中的角色**：创新求解主引擎，对应分析（03）与综合（04）阶段。

### 2. PRISMA —— 系统综述报告规范（证据综合流水线）

PRISMA（Preferred Reporting Items for Systematic Reviews and Meta-Analyses）以"**识别 → 筛选 → 合格性 → 纳入**"（Identification → Screening → Eligibility → Included）四级筛选级联（screening cascade）规范系统文献综述的可复现性，并辅以**偏倚风险表（risk-of-bias table）**。

- **特征**：过程透明、偏倚可控、结果可审计；把"找文献"从随意检索变为受控的证据筛选。
- **在 TRINNO 中的角色**：文献发现（01_Discover）与证据归档（06_References）的方法论底座，由 `/search`、`/download`、`/get`、`/papers` 承载。

### 3. SWOT（+TOWS）—— 战略态势分析（方案评估框架）

SWOT 从优势（Strengths）、劣势（Weaknesses）、机会（Opportunities）、威胁（Threats）四维作内外部、正反双向权衡；TRINNO 进一步支持 **TOWS**（由外部环境反推战略组合）以衔接策略生成。

- **特征**：简洁、对称、决策导向；将多维定性判断收敛为可比的战略态势。
- **在 TRINNO 中的角色**：方案交付（05_Deliver）前的战略评估与取舍依据。

### 4. PEST / PESTEL —— 宏观环境扫描（环境约束框架）

PEST 从政治（Political）、经济（Economic）、社会（Social）、技术（Technological）四维扫描创新所嵌入的宏观环境；可扩展为 **PESTEL**（增加环境与法律维度）。

- **特征**：外生视角、前瞻性强；识别技术之外的采纳壁垒与机遇窗口。
- **在 TRINNO 中的角色**：对创新方案作环境与可行性校验，防止"技术可行、环境不可行"。

### 5. 5W1H —— 全维追问框架（问题界定入口）

5W1H（Who / What / When / Where / Why / How）以六个基本疑问对模糊诉求作结构性拆解。

- **特征**：低门槛、全覆盖、强制显式化；把"我想要个更好的方案"转译为可操作的任务维度。
- **在 TRINNO 中的角色**：任务分解与问题界定的第一入口，为后续框架提供结构化输入。

### 6. PICO / PICOS —— 研究问题结构化（证据检索骨架）

PICO 将研究问题形式化为 **P**opulation（人群）/ **I**ntervention（干预）/ **C**omparison（对照）/ **O**utcome（结局）四要素；临床与循证场景可扩展为 **PICOS**，追加 **S**tudy design（研究设计，如 RCT、队列研究）。

- **特征**：可检索、可证伪、边界清晰；使检索式与目标证据一一对应。模板：`In [P], does [I] vs [C] affect [O]?`
- **在 TRINNO 中的角色**：将 5W1H 的拆解结果编译为可执行的证据检索问句，驱动 PRISMA 流程（PICO 为 PRISMA 的上游输入）。

## 二、方法论路由：有机智能体的"智能"所在

六套框架若机械串联，只是工具清单；TRINNO 的差异化在于其**有机性**——智能体依据问题类型**自动路由**到最适配的框架组合，而非固定走完所有流程。这一路由机制是其"智能"的核心体现：

| 问题类型 | 路由（Methodology Routing） |
|---|---|
| 技术壁垒 / 发明问题 | **TRIZ** 矛盾矩阵 |
| 新技术 / 新市场研判 | **S 曲线 + PEST** |
| 临床 / 生物医学循证问题 | **PICO** 界定问题 → **PRISMA** 系统综述 |
| 战略 / 竞争分析 | **SWOT + PEST** |
| 证据综合 / 文献综述 | **PRISMA** |
| 范围不明 / 非结构化问题 | 先 **5W1H** 界定 |

此外，TRINNO 在证据检索上落实"双语并行"原则：对任一主题**同时发起英文（EN）与中文（ZH）查询**，并以 DOI / arXiv ID 去重（覆盖中文期刊如《自动化学报》《控制与决策》《机器人》等），证据源涵盖 Semantic Scholar、OpenAlex、Google Patents、USPTO 等，并对 PubScholar 等开放入口做适配。

一个典型的有机生命周期如下（智能体可按需裁剪或跳转）：

```
5W1H   界定问题边界与任务维度
  ↓
PICO   将界定结果结构化为可检索证据问句
  ↓
PRISMA 执行系统综述（识别→筛选→合格→纳入），沉淀受控证据集
  ↓
TRIZ   基于证据对矛盾作创新求解（矛盾矩阵 / 物场 / 理想度 / S 曲线）
  ↓
SWOT   对候选方案作战略态势评估（TOWS 衔接策略）
  ↓
PEST   在宏观环境中校验可行性与风险
```

其"有机"体现在三方面：

1. **上下文感知的路由**：智能体识别问题类型，动态调用对应框架（见上表），而非一律全流程跑遍。
2. **框架间的信息继承**：上游产出是下游的结构化输入（5W1H → PICO → PRISMA），形成不靠人工搬运的连贯链路。
3. **人机协同闭环**：方法论提供方向与约束，AI 加速执行与综合，工程判断仍由人主导——智能体压缩的是"从问题到可行方向"的认知距离。

## 三、与工程基座的映射

有机编排需落于具体能力。TRINNO 以 **八阶段工作区 TRP**（01_Discover → 02_TRL → 03_Analyze → 04_Synthesize → 05_Deliver → 06_References → 07_Patent → 08_AutoResearch）固化流程，并以斜杠命令承载框架调用：

- **工作区与治理**：`/init`（脚手架初始化）、`/goal`（持久研究目标与分解）、`/compact`（历史压缩）、`/undo`（基于 jj 的快照回退）；
- **检索与下载（PRISMA/PICO）**：`/search`（多源先验检索）、`/download`（9+ 源竞速下载器）、`/get`（检索并自动下载首选）、`/papers`（已下载文献索引）；
- **TRIZ 求解**：`/contradiction`、`/principles`、`/ideality`、`/su-field`、`/s-curve`；
- **写作交付**：`/patent <标题>`（增量式专利草稿）、`/write paper: <标题>`（Typst 排版论文）；
- **自主研究**：`/auto <假设>`（假设驱动迭代，至目标达成或受阻）。

## 四、共同特征

综观六套方法论与智能体基座，TRINNO 呈现四项贯穿性特征：

1. **方法论工程化**：将理论框架编译为编辑器内可调用命令，消除使用门槛。
2. **证据闭环**：5W1H/PICO 定义问题 → PRISMA 综合证据 → TRIZ 求解 → SWOT/PEST 评估，结论皆有据可依。
3. **结构化与可复现**：TRP 阶段固化流程，创新过程可归档、可复盘、可交接。
4. **有机而非机械**：智能体按问题类型路由并编排框架，兼顾系统性与灵活性。
