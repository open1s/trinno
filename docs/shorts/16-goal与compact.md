# 16 /goal 目标护栏与 /compact 历史压缩：让对话不跑偏、不爆窗

多步研究最怕两件事：一是**对话偏离初衷**，二是**上下文窗口被长历史撑爆**。TRINNO 用 `/goal` 与 `/compact` 分别治理这两个风险，使智能体在长程任务中保持定向与可控。

## 一、/goal：持久目标与契约式分解

```
/goal 探索固态电解质界面稳定性优化方案
```

设定后，TRINNO 将目标**持久化**，并在下一条消息自动将其**分解为可执行的子任务与验收标准**。其底层是一个目标状态机，状态包括：

- `active`（活跃，触发续跑）、`paused`（暂停）、`blocked`（受阻）、`complete`（完成）、`budget_limited` / `usage_limited`（受预算或用量限制终止）。

目标的**验收标准（acceptance criteria）**构成"契约"：智能体产出须对照标准自检，而非开放式闲聊。进展可记录为 `completed/total` 的进度项。

## 二、预算与用量护栏

状态机中的 `budget_limited` 与 `usage_limited` 体现 TRINNO 的**资源治理**：当消耗逼近预算或调用量上限时，智能体主动停止而非无限蔓延。这与 `/auto` 的 `eval.md` 锁定、循环终止条件同源——都是"让自主行为可被治理"的设计哲学。

## 三、/compact：历史压缩救上下文

长对话会触及上下文窗口上限。TRINNO 的**压缩（compaction）**机制将对话历史摘要为 `systemSummary` 并追加进系统提示，释放窗口压力。用户亦可主动 `/compact`。

结合 `chat.context.maxTotalTokens` 等设置，可调控上下文预算；`@<path>` 引用与 `@` 自动注入则让工作区文件成为隐式上下文。

## 四、会话与持久化

- 每次对话是一个**会话（session）**，会话名显示于状态栏；
- `Ctrl+N` 新建会话、`Ctrl+Z` 删除；
- 会话经 `chat.history.enabled` 跨 VS Code 重启持久化（默认保留 100 条消息）。

## 五、小结

`/goal` 给智能体装上"目标罗盘 + 预算闸"，`/compact` 解决"记忆溢出"。二者共同保障长程研究的定向与可持续。下一期看另一类上下文治理——混合附件策略（ADR-001）。
