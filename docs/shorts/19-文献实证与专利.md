# 19 文献实证与 /patent：让结论落进可辩护的交付物

创新工作的最终价值，体现在**可交付、可辩护**的产出上。TRINNO 以 **06_References 证据闭环** 与 **/patent 增量式专利草稿**，把前面的分析成果收口为带真实引用的成果物。

## 一、06_References：实证闭环的蓄水池

所有下载文献默认归入工作区 `06_References/`：

```
06_References/
├── library.md      # 全部参考文献索引（自动维护）
├── 目录.md         # 中文分类目录（可手建类别）
└── papers/         # 下载的 PDF / 文档
    ├── 10.1038_nenergy.2016.141.pdf
    └── arXiv_2304.12345.pdf
```

最佳实践：

- 用 `/get <query>` 一步完成检索 + 下载首选；
- 已知标识符时直接用 `/download <DOI>`；
- 用 `/papers` 盘点已下载文献；
- 读后给 `library.md` 标注重要性评分；
- 用 `目录.md` 作为活的目录，按需分类。

## 二、/patent：增量式、受实证约束的专利草稿

```
/patent 一种基于梯度孔隙结构的气体扩散层
```

TRINNO 的专利起草遵循两条铁律：

1. **增量式**：LLM 逐节撰写，每轮 1–2 节，用户在节间审阅、用 `/undo` 回退错误节；
2. **强制真实引用**：专利/论文中每一条参考文献，都必须以 `06_References/` 中的真实文件存在为前提——**杜绝编造引用**。

因此推荐工作流是"先检索、后起草"：

```
/search 先验技术       # 建立证据背景
/download 关键文献     # 落盘真实引用
/patent <标题>         # 基于真实证据撰写
```

## 三、与论文交付的衔接

`/write paper: <标题>` 以 Typst 排版启动研究论文（注意冒号 + 标题是明确触发，缺省则智能体会先追问而非臆造主题）。论文同样受实证闭环约束。

## 四、在链路中的位置

文献实证与专利起草是解法链路的**收口段**：

```
TRIZ 方案 → SWOT/PEST 评估 → 06_References 实证支撑 → 05_Deliver / 07_Patent
```

没有实证闭环，方案只是主张；有了真实引用，成果才可被评审、可被抗辩。

06_References 与 /patent 把"分析"变为"资产"。下一期，我们用一个端到端实战把全系列串起来，并给出体系总图。
