# 03 5W1H：把模糊诉求拆成可操作维度的第一入口

最难的不是求解，而是**把问题说清楚**。一句"我们想要个更好的电池"，既是工程诉求，也是一句无法被任何方法论直接消费的模糊表述。TRINNO 的应对之道，是用 **5W1H** 作为问题界定的第一入口，将含糊意图转译为结构化、可路由的任务维度。

## 一、5W1H 是什么

5W1H 以六个基本疑问对问题进行全维拆解：

- **Who（谁）**：受益/受影响对象、使用者、干系人；
- **What（什么）**：要解决的对象、当前状态与目标状态；
- **When（何时）**：时间约束、里程碑、生命周期阶段；
- **Where（何处）**：应用场景、部署环境、地理/组织边界；
- **Why（为何）**：根本动因、约束来源、价值诉求；
- **How（如何）**：实现路径、资源与方式约束。

其价值不在答案本身，而在于**强制显式化**——把隐含假设逼到台面，暴露出真正需要决策的焦点。

## 二、在 TRINNO 中的角色：路由起点

5W1H 在方法论路由中占据特殊位置。当问题**范围不明或非结构化**时，TRINNO 优先以 5W1H 界定边界，再据此选择后续框架：

```
范围不明 / 非结构化问题  →  先 5W1H 界定
        ↓
按维度结果路由：技术壁垒→TRIZ，战略→SWOT+PEST，循证→PICO→PRISMA
```

这一"先界定、后路由"的机制，正是智能体区别于关键词工具的体现：它先理解问题，再决定用什么方法。

## 三、行为约定：一次一问，有序澄清

TRINNO 对模糊问题遵循明确的澄清纪律（见 `docs/persona.md`）：**以一次一个问题、附有序选项的方式追问，直至清晰**，而非一次性抛出大量反问。这既降低用户负担，又保证每一轮都收敛问题空间。

例如针对"更好的电池"，智能体可能先问 *Why*（是能量密度、寿命还是成本优先？），再问 *Who/Where*（车载还是消费电子？），逐步锁定问题的真实维度。

## 四、向下游交付结构化输入

5W1H 的产出不是终点，而是下游框架的喂料：

- 界定出的"对象 + 干预 + 对照 + 结局"线索，可直接编译为 **PICO** 证据检索问句；
- 识别出的技术壁垒维度，引导 **TRIZ** 矛盾分析；
- 提取出的战略与环境因素，分别进入 **SWOT** 与 **PEST**。

换言之，5W1H 是整条链路中"把人话翻成方法语言"的翻译层。

## 五、小结

5W1H 门槛低、覆盖全，却处在方法论链条最关键的起点。它让 TRINNO 从"你说一句它答一句"的聊天工具，变成"先帮你把问题想明白"的研究协作者。下一期，我们看界定之后如何把问题编译成可检索的证据骨架——PICO。
