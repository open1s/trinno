# PRD: AI Chat UI for Trinno

## Problem Statement

Academic researchers using Jupyter notebooks with Typst cells lack an AI assistant that understands both their notebook context and their domain (TRIZ-based research). Existing AI chat tools are disconnected from the notebook workflow — researchers must copy/paste content, manually apply suggestions, and switch between tools.

## Solution

A floating chat panel (Claude Code-style) integrated into the VS Code extension, backed by an ezbos-powered AI agent with TRIZ research tools and autonomous notebook cell insertion.

## User Stories

1. As a researcher, I want to open a chat panel from VS Code (`Ctrl+Shift+C`), so I can ask questions without switching applications.
2. As a researcher, I want the chat panel to automatically see my notebook context at conversation start, so I don't have to re-explain my work.
3. As a researcher, I want streaming responses with collapsible reasoning sections and inline tool call badges.
4. As a researcher, I want the AI to search patents/papers and perform TRIZ analysis.
5. As a researcher, I want the AI to autonomously insert new Typst cells into my notebook at cursor position.
6. As a researcher, I want an "Undo" button to reverse the last AI-inserted cell.
7. As a researcher, I want to configure which AI model is used (provider, API key, endpoint).
8. As a researcher, I want to customize the agent persona (name, system prompt).
9. As a researcher, I want chat history to persist across VS Code sessions.
10. As a researcher, I want paste/drop content in chat input, Typst code insert buttons, and inline image rendering.

## Implementation Decisions

### Architecture
- WebViewPanel in VS Code sidebar, ezbos in Extension Host, postMessage bridge
- Lazy ezbos initialization on first chat interaction
- Chat history in `<workspace>/.vscode/trinno-chat-history.json`

### Modules
| Module | Responsibility |
|--------|----------------|
| `chat/settings.ts` | Configuration schema, defaults, secrets |
| `chat/messages.ts` | Message types, serialization |
| `chat/context.ts` | Notebook context extraction (`get_notebook_context` tool) |
| `chat/agent.ts` | ezbos Agent lifecycle, streaming, TRIZ tools, `insert_cell` tool |
| `chat/panel.ts` | WebViewPanel management, message routing |
| `chat/webview/*` | HTML/CSS/JS for chat UI |
| `extension.ts` changes | Register commands, webview provider, lazy init |

### Tools
- `get_notebook_context` — system tool (hidden from UI), auto-called at conversation start
- `insert_cell` — user-visible, inserts Typst/code/markdown cell at cursor or end
- TRIZ tools: `triz_trigger_search_prior_art`, `triz_analyze_contradiction`, `triz_analyze_s_curve`, etc.

### PostMessage Protocol
- Extension→WebView: `{ type: 'token', tokenType, text }`, `{ type: 'done' }`, `{ type: 'error', message }`, `{ type: 'welcome', context }`
- WebView→Extension: `{ type: 'userMessage', text }`, `{ type: 'cancel' }`, `{ type: 'undoInsert' }`

### Settings
- Model: provider, name, apiKey (secrets), baseUrl
- Persona: name, system prompt
- Streaming: showThinking, thinkingFlushInterval
- Context: autoInject, maxCharsPerCell (500), maxTotalTokens (4000)
- History: enabled, maxMessages (100)

### Error Recovery
- Stream drop: retry once with 2s backoff, then show inline error + retry button

## Testing
- Test agent initialization with correct tools/persona
- Test notebook context extraction with mocked VS Code API
- Test `insert_cell` at correct position
- Test postMessage round-trip and streaming rendering
- Observable behavior only, no internal implementation tests

## Out of Scope
- Live preview while typing, cell modification, file writes, image generation
- Multi-agent, kernel execution, VS Code Chat API, `@` mentions, voice

## Further Notes
- `bos/` directory kept as-is from ddbos copy
- Panel uses `var(--vscode-*)` CSS variables for theme compatibility
- ezbos system prompt includes notebook context instructions + TRIZ knowledge
- `insert_cell` is the only autonomous write; all others are read-only
