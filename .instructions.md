# Trinno Agent Instructions

## Project Identity
**Trinno Research Assist** — VS Code extension for AI-powered TRIZ-based research. Adds Trinno Chat sidebar panel + Jupyter notebook integration. Core mission: help researchers structure innovation analysis through 7-phase workflow.

## Critical Constraints

### 1. DO NOT Violate These
- **Never edit these folders**: `node_modules/`, `dist/`, `tride/` (external dependency)
- **Never change tsc-excluded logic**: `src/bos/` is excluded from TypeScript checking intentionally. Don't try to fix LSP errors there; trust runtime + `npm run compile`
- **Always compile before testing**: `npm run compile` MUST succeed before `npm run test`
- **Preserve phase directory structure**: All output must respect the 7-phase model (01_Discover through 07_Patent)

### 2. Mandatory Workflow Rules
- **Incremental edits only**: Use `multi_replace_string_in_file` for multiple changes; never rewrite entire files
- **Task atomicity**: Break work into single-purpose chunks; mark ONE todo as in-progress at a time
- **Parallel execution for independent reads**: Use parallel file_search/grep_search/read_file calls; never call semantic_search in parallel
- **Success verification**: After edits, run `npm run compile` to validate TypeScript; run tests if changing core logic

## Task Decomposition Rules (Prevent LLM Timeout)

### Pattern 1: Multi-File Changes
**INSTEAD OF**: "Refactor the agent to use new pattern everywhere"
**DO THIS**:
1. Analyze current state (read all affected files)
2. Design change (output brief 3-step plan)
3. Apply ONE file at a time:
   - Change file A → verify compiles
   - Change file B → verify compiles
   - Change file C → verify compiles

### Pattern 2: Complex Features
**INSTEAD OF**: "Implement the full /analyze-contradiction feature"
**DO THIS**:
1. **Phase 0: Setup** — Create domain model class, add to DI container
2. **Phase 1: Core logic** — Implement contradiction analysis algorithm
3. **Phase 2: Integration** — Wire into slash command registry + panel
4. **Phase 3: UI** — Add webview UI (if needed)
5. **Phase 4: Tests** — Write integration test
Each phase is a separate response; state "Next: [Phase Name]" before responding

### Pattern 3: Debugging Long Issues
**INSTEAD OF**: "Debug this crash and fix it"
**DO THIS**:
1. Gather facts: stack trace, environment, reproduction steps
2. Form hypothesis: "I believe X is happening because Y"
3. Design minimal test: Write single test that isolates the issue
4. Fix: Make ONE focused change
5. Verify: Run test + `npm run compile`
Do NOT attempt multi-step debugging in one response; pause after each step

### Pattern 4: Documentation Changes
**INSTEAD OF**: "Update all agent docs for new workflow"
**DO THIS**:
1. Create/edit ONE file at a time
2. After each file: "Next file: [path]"
3. Validate: Check links and formatting before moving on

## Response Size Strategy

### When to Stop and Pause
- More than 5 file edits needed → Stop after 3, say "Next batch: [files]"
- More than 2 code generations → Stop after 1, ask for feedback
- More than 3 paragraphs of explanation → Truncate, ask clarifying questions
- More than 10 research calls → Pause and summarize findings

### When to Parallelize
- Independent `read_file` calls → combine in one block
- Multiple `grep_search` in different files → combine in one block
- Multiple unrelated edits → use `multi_replace_string_in_file`

### When to Serialize
- Any edit that depends on previous result → wait for output
- `npm run compile` must finish before `npm run test`
- Async terminal commands → check output before next step

## Tool Priority Ranking

1. **edit tool** (fastest, surgical): Use for 1-3 line changes
2. **multi_replace_string_in_file** (parallel safe): Use for ≥2 independent edits
3. **run_task** (compile/test): Always use instead of run_in_terminal for npm tasks
4. **run_in_terminal** (only for): non-npm commands, debugging, interactive setup
5. **refactor tools** (slow, use sparingly): Only when LSP renaming is essential

## Code Style Anchors

### TypeScript Strictness
- `strictNullChecks: true`, `exactOptionalPropertyTypes: true`
- Imports use `.js` extension (CommonJS module resolution)
- `E0277`, `E0308`, `E0599` are real errors, not LSP noise

### File Locations Matter
- **User-facing logic**: `src/chat/` (webview host, panel, sessions)
- **AI orchestration**: `src/bos/` (worker, tools, slash commands)
- **Data I/O**: `src/papers/` (downloader, sources, search)
- **Testing**: `src/test/suite/` (Mocha + @vscode/test-electron)

### Naming Conventions
- Slash commands: `/kebab-case` (registered in `worker.ts` + `panel.ts` + `chat.js`)
- Tool names: `camelCase` (defined in `triz_tools.ts`, `papers_tools.ts`)
- Phase directories: `NN_CapitalCase` (01_Discover, 02_TRL, etc.)

## Common Pitfalls & Recovery

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| LSP errors in `src/bos/` | Red squiggles in editor | Ignore; trust `npm run compile` |
| Changes not reflected in tests | Test still fails after edit | Did you run `npm run compile`? Yes? Check `dist/` has new code |
| Worker process crashes | Agent panel shows error | Check worker.ts syntax; run `npm run compile` with `--showErrors` |
| Attachment strategy broken | File references not working | Verify `hybrid_attachment_strategy.md` ADR rules in `context.ts` |
| Phase output in wrong directory | Files end up in wrong folder | Check `PhaseWriter` construction in slash-command file |
